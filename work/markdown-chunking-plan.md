# Markdown support and semantic merging implementation plan

Build the Markdown parser and a section-aware greedy packer first. Compare packing, scoring the original adjacent units once, and semachunk’s current strategy of rescoring merged neighbors. Use the same units and size rules for all three. Ship the simplest method that earns its place on retrieval and cost. Test heading context on the winner. Build a window scorer only if changing merge order affects retrieval.

## 1. Parse Markdown and establish the packing baseline

Add `inputFormat: 'markdown'` to `chunkText(text, embedBatch, options)`. Parse before the plain-text path normalizes whitespace. Use `mdast-util-from-markdown` with the GFM and frontmatter extensions. Load them lazily as optional peers, install them for development and give Markdown callers an actionable missing-package error. Skip recognized leading YAML without parsing its values. An unclosed delimiter follows ordinary Markdown parsing. Document attributes belong to the caller. [Markdown parser](https://github.com/syntax-tree/mdast-util-from-markdown/blob/afe9516d97683e51974694f944a799a915a242c0/readme.md) · [GFM](https://github.com/syntax-tree/mdast-util-gfm/blob/6b34bb2868c38c0b2909fa69c78534d5e44dc309/readme.md) · [Frontmatter](https://github.com/syntax-tree/mdast-util-frontmatter)

Walk blocks in source order. Give the preamble its own section and identify each later section by its heading’s UTF-16 source offset. `headingPath` contains visible heading text. Attach consecutive active headings to their first body where the hard cap permits, keeping them in metadata otherwise. Superseded empty sections and trailing headings produce no chunk. Empty, frontmatter-only and headings-only documents return `[]` without embedding. Headings inside lists and quotes stay in their container. A top-level thematic break separates runs without producing a chunk.

Keep Markdown reference syntax in the body. The caller uses the original document to resolve `[policy][p]` and footnote references for display. Leave link-target declarations in the source and index substantive footnote text once at its definition. Embedded HTML in Markdown stays literal. Any skipped source block is a merge barrier so a later slice cannot bring it back. [GFM reference definitions](https://github.github.com/gfm/#link-reference-definitions) · [GFM parser extensions](https://github.com/syntax-tree/mdast-util-gfm)

**Size and split order.** Use the existing 500 UTF-16 code units as the default `maxChunkSize` for joins. It guides natural splits within large Markdown blocks and an indivisible leaf may exceed it. A finite `maxChunkTokens` uses the caller’s `countTokens` and is hard. Count the actual raw and prefixed strings, including repeated headers and generated markup. Use each block’s natural splits when either applicable limit is exceeded, including with `maxChunkSize: Infinity`. Code stays intact under a character-only target. Recount the full candidate for a hard cap because token counts can change at a join. [Current options](../README.md) · [Token limit](../src/token-limit.js)

| Block | Initial units and natural splits | Fallback under a hard token cap |
| --- | --- | --- |
| Paragraph | Keep a fitting paragraph whole. Otherwise expose sentence units using offsets in the original paragraph. Protect inline links and code when choosing sentence boundaries. | Cut a remaining oversized sentence at whitespace, then at Unicode code-point boundaries. Break protected inline content only if the span itself cannot fit. |
| List or blockquote | Keep a fitting container whole. Otherwise descend through its items or child blocks, keeping markers, indentation and continuation lines. | Apply the child’s split rule. Account for the enclosing list or quote prefix when a continuation needs one. |
| GFM table | Keep a fitting table whole. Otherwise take complete rows with the original header and delimiter. One row may exceed the character target. | If even one row with its header cannot fit, emit source fragments of the oversized material within the cap. Keep every value in source order. Reattaching a full header over a partial row can put values under the wrong column. |
| Code | Keep a fitting fenced or indented code block intact. | Split by lines, then split an oversized line. For fenced continuations preserve the fence character, info string and container prefix. Use a fence long enough for the fragment. |

Read container prefixes and the table delimiter from source lines. In a quoted table the parser’s row begins after `> ` and its delimiter has no row node. Keep each whitespace character on one side of a cut, preserve indentation and line endings, and advance by a whole code point. `splitToFit` returns strings and can drop the separating space. Reuse its cut logic through a path that returns lossless source spans. If a wrapper cannot fit, fall back to raw source fragments. Throw a clear error if even one code point with the required caller prefix cannot fit. [Existing splitter](../src/token-limit.js) · [GFM tables](https://github.github.com/gfm/#tables-extension-)

Markdown results add `sectionId`, `headingPath` and `sourceRanges` to `text` and optional `embedding`. Use a Markdown literal overload and keep a usable return type for callers with a variable input format. Each range `{ start, end, outputStart }` addresses half-open UTF-16 offsets in the caller’s input and the actual returned `text`. Assert `text.slice(outputStart, outputStart + end - start) === input.slice(start, end)` for every range. Also check coverage and order. Every retained body span must appear once apart from deliberate repetitions. A repeated verbatim table header maps to the original header each time. Generated markup and a visible caller prefix occupy unmapped positions. Identical bodies at different positions retain distinct occurrences.

Verify ranges with a leading BOM (compensate once), CRLF, emoji, setext headings, nested containers, repeated `1.` list markers, escaped pipes, overlong cells, fence-like code lines and punctuation inside links. Include closed frontmatter with invalid YAML, an unclosed delimiter, a numeric-only table, code indentation and a footnote whose definition is in a different section. Apply `excludeNonLetterSentences` to prose sentence filtering only.

**Reuse and licensing for this work.** Use existing libraries where their APIs fit. Verify the license of the specific source files before copying or translating code and retain the notices required for semachunk's MIT distribution. With incompatible terms, implement the idea independently from published behavior or an algorithm description. Even with compatible terms, use a direct semachunk implementation when it avoids adapters. Chunkdown's list and table splitters are behavioral references here. The source-slice approach makes a port unnecessary. [Chunkdown lists](https://github.com/zirkelc/chunkdown/blob/facdf3532ac288e446331c295d87d7b3ace8301d/src/splitters/list.ts) · [Tables](https://github.com/zirkelc/chunkdown/blob/facdf3532ac288e446331c295d87d7b3ace8301d/src/splitters/table.ts#L85) · [License](https://github.com/zirkelc/chunkdown/blob/facdf3532ac288e446331c295d87d7b3ace8301d/LICENSE)

### HTML at ingestion

Use an existing Node pipeline for callers that have HTML. Run `rehype-parse` → `rehype-remark` → `remark-gfm` → `remark-stringify`, then pass the resulting string to the Markdown entry point. Source ranges refer to that string. Ship the opt-in Markdown path independently of the existing `inputFormat: 'html'` plain-text extractor. Changing that public option would change callers’ chunk boundaries. Revisit a thin built-in conversion adapter after checking representative HTML sources. [Current HTML extractor](../src/sentences.js) · [rehype-remark’s conversion example](https://github.com/rehypejs/rehype-remark/tree/f740c02d583318904be6cd4b3539e7350983ece8#use) · [GFM support](https://github.com/remarkjs/remark-gfm)

A Node smoke test on three synthetic fragments shows where this is worthwhile. With `rehype-remark@10.0.1` and `remark-gfm@4.0.1`, a mismatched heading end tag, list and data table became a Markdown heading, list and labeled table. A CSS-styled `div` heading became ordinary text. A `role="presentation"` navigation table still became a Markdown table. Check representative source pages for headings, labels and reading order before adopting the convenience adapter. For sources that fail, use available extracted text or a source-specific upstream extractor. Keep site-specific repair out of the chunker.

## 2. Compare three ways to combine the same units

Keep parsing separate from combination. With `combineChunks: false`, return the budget-safe initial units. With `returnEmbedding: false` as well, make zero embedding calls. Greedy packing needs vectors only when the caller asks for final embeddings. A semantic strategy can still need scoring vectors when final embeddings are disabled. Preserve `maxPasses: 0` on the priority path. Reject `groupSentences: true` in Markdown v1. Its sentence-centroid pass has weak evidence for paragraphs. Document the options supported by the winning strategy before exposing it. [Entry point](../src/index.js) · [Earlier grouping results](../benchmarks/LOG.md)

All candidates respect each section occurrence and source order. A mergeable run contains only contiguous source and its whitespace separators. Its join is `input.slice(left.start, right.end)` and its UTF-16 length is `right.end - left.start`. Carry the endpoints through combination and render the text when needed. Fragments with generated wrappers are terminal. Use the same join rule for eligibility, token counting, scoring, queue pruning and final output. The current heap uses `+ 1` and a literal space in more than one place. Test a CRLF/blank-line join close to the limit. [Current merger](../src/merge.js)

| Candidate | Decision at a boundary | Embedding work |
| --- | --- | --- |
| Section-aware greedy packing | Scan in document order and append the next eligible unit while it fits. | Requested final indexing texts only. [Docling’s `merge_peers`](https://docling-project.github.io/docling/concepts/chunking/#hybrid-chunker) |
| Score each original boundary once | For the gap between original units B and C, store `cos(B, C)`. If A+B later meets C+D, use that stored score. Recheck the live join’s structural and size limits. | Batch the original units needed at possible boundaries. For `n` units, compute at most `n − 1` dot products of normalized neighbors. Batch the requested final texts. Aurelio uses consecutive-split cosine. Our experiment keeps semachunk’s best-first order and pass caps. [Aurelio implementation](https://github.com/aurelio-labs/semantic-chunkers/blob/c3362249b792e8558866e6f81e614025cceb1bbc/semantic_chunkers/chunkers/consecutive.py#L28-L52) |
| Rescore after merging | For the same live pair, use `cos(A+B, C+D)` on the exact joined bodies, including attached source headings. | Batch changed bodies and update only their neighboring scores with the current priority merger. [Merger](../src/merge.js) · [Batch embedder](../src/embeddings.js) |

Prototype both semantic candidates with the same document-wide queue, stable tie order, disjoint merges and pass caps. Preserve batch limits, cache policy and final-vector reuse by exact string. Avoid one request per section or pair. A document with a single distinct missing input can still produce a singleton. Compare fixed cutoffs 0.3, 0.5 and 0.7 on calibration and log the cosine distribution of initially eligible boundaries. Compute a document-adaptive cutoff only from those boundaries when testing the existing opt-in mode. Chaining strong local pairs can join drifting topics, so inspect where the two scoring methods actually choose different evidence.

Protect tables and code on both sides for the main comparison. On calibration, separately test a single original prose unit joining the immediately following intact block in the same section, then close that combined unit to further joins. Measure it first where lead-in text and a table or command belong together. Apply the same rule across candidates. Defer joining small sibling sections until FAQ or API retrieval shows lost evidence worth the added source metadata. [LightRAG’s structural checks](https://github.com/dargoner/lightrag-java/blob/af70d08df7fd7fb2b6d979321f05008d9c250305/lightrag-core/src/main/java/io/github/lightrag/indexing/SemanticChunkRefiner.java#L161)

**Release decision.** Build the comparison in the harness before refactoring the production heap. Ship packing if it is competitive. Ship a semantic strategy only for a retrieval gain worth its cost, and require the rescoring variant to justify its intermediate embeddings against the fixed-boundary variant. Integrate only the winner. Cover section barriers, identical text at distinct positions, disjoint selection, globally batched calls, final-vector identity and the existing plain-text behavior.

## 3. Evaluate heading context on fixed chunks

Freeze the winning source spans and delivered text. The baseline indexes the *actual* required caller prefix plus body, even when `excludeChunkPrefixInResults` hides that prefix. Compare heading context with this baseline. Where titles are available, include a title-only control to tell how much the heading path adds beyond the document title. Deduplicate existing leading headings in the added context. Keep the body, required prefix and retrieval prompt identical across arms. [Docling contextualization](https://docling-project.github.io/docling/concepts/chunking/#base-chunker)

Render the experimental index strings **after** creating the fixed bodies. A 256-token experimental body target can then be paired with the harness’s 8,192-token provider ceiling. Also run the intended deployment cap and report how often context is retained, shortened or omitted. Drop outer ancestors first and keep an optional title until last. A real `chunkText` call always honors its explicit `maxChunkTokens`, including its required prefix. [Harness limits](../benchmarks/encoder.mjs)

For Markdown, return `embeddingText` whenever the exact indexing string differs from `text`, including with `returnEmbedding: false` for external indexing. Test a hidden caller prefix, a full body, zero passes and a finite cache. If the title alone accounts for the gain, use the existing `chunkPrefix` option. Expose `embeddingContext: 'headings'` only if the path adds value. Defer a separate table experiment rendering rows as `Header: value` to index time if row evidence is often missed.

## 4. Test whether merge order matters before building windows

Run this stage only if whole-body priority rescoring wins. In calibration, reverse the priority of passing pairs with the cutoff, size rules, ties and pass caps held fixed. Record competing pairs, changed final boundaries and changed answers. When even reversing the ranking rarely changes retrieval, stop here for that workload.

If order matters, keep whole-body cosine for eligibility. Preselect prose documents where each mergeable unit has a first and last sentence that individually fit the hard limit. Rank using up to two sentences on either side of the boundary, shortening a side to one when needed. Use ordinary ordering on the other documents and report coverage. Each document’s queue then uses a single score scale. Batch unique window strings across the document, reuse exact vectors and update only changed neighbors. Test rank reversals and blocked pairs, and count singleton calls.

The matched WikiSection diagnostic measured boundary AUC of 0.786 for two sentences per side and 0.631 for one. Three per side had no eligible gold boundaries. Retrieval on fixed budgets decides whether to adopt it. Defer ChonkieJS’s asymmetric window and pooling existing sentence vectors until the two-sided experiment shows a gain worth pursuing. [Matched diagnostic](../benchmarks/LOG.md#cutoff-size-and-grouping-experiments) · [ChonkieJS](https://github.com/feyninc/chonkiejs/blob/53d4b54fa2be9e20819c36f56ce6bd50e9f0630e/packages/core/src/semantic.ts#L365) · [Aurelio pooling](https://github.com/aurelio-labs/semantic-chunkers/blob/c3362249b792e8558866e6f81e614025cceb1bbc/semantic_chunkers/chunkers/statistical.py#L285)

## Benchmark and release decisions

Freeze the document IDs, renderer, evidence mappings and candidate pools before tuning. Keep the published samples as historical regressions. Split fresh material by contract, paper or financial report. Keep questions sharing HotpotQA passages in the same split. Use calibration for body size, cutoff, candidate selection and optional experiments. Freeze the shortlist and its simpler comparators before opening the final evaluation set. A new idea arising from those results needs fresh confirmation.

| Comparison | What stays fixed |
| --- | --- |
| Public defaults | Run both plain text and Markdown on the same source with 500 UTF-16 units and the token cap disabled. Also keep the published plain-text 500-unit, cosine-0.5 row on its original data. |
| Plain sentence packing and priority merging | For the matched token runs, use the same source, candidate pool, tokenizer and budgets as Markdown. Fix the harness’s `pack` branch first. Today it checks only `maxChunkSize` when joining and can pack the entire document with `Infinity`. Test both an oversized seed and an oversized join. [Packing control](../benchmarks/chunking.mjs) |
| Fixed token windows | Include today’s 128-token window with 32-token overlap and one window at the selected common chunk budget. Declare its overlap before comparing. |
| Markdown combination | Use the same parser units, section boundaries and block protections for greedy packing and both semantic candidates. Add sentence-split prose under the same headings on QASPER to measure how much comes from matching its paragraph labels. |
| Heading context and window ranking | Change one factor at a time. Freeze bodies for context and freeze whole-body eligibility for ranking. Combine optional features only after each earns its cost on calibration. |

Select the common chunk size on a preselected plain-text control at 128, 256 or 512 body tokens with `maxChunkSize: Infinity`. Exact tokens here make the comparisons reproducible. Ordinary production sizing needs only character lengths. Fix the independent **retrieved context** budgets at 256, 512 and 1,024 tokens. Measure final indexing costs in every arm.

### What the retriever actually sees

Keep each passage occurrence with its document, returned `text`, source mapping and exact indexing string. Identical strings can share a vector and still represent different evidence locations. Rank dense retrieval by the indexed vector. Use the delivered body for the BM25 control when varying only embedding context. In the Node harness, record actual embedding inputs as the chosen boundaries become known and replay by model configuration and exact string. Batch misses and keep the current provider limits. Report logical cold calls, texts and singleton batches separately from paid requests, cached vectors and replay time. [Current harness](../benchmarks/chunking.mjs) · [Benchmark encoder](../benchmarks/encoder.mjs)

Budget the literal retrieved bodies in rank order, joined by a fixed `\n\n`. Tokenize the serialized context including separators, repeated headers and generated fences. Clip the last body to a complete Unicode character and verify the resulting count. The existing scorer charges `p.end - p.start` from the *source* tokenization. Even `hel` and `lo` cost two tokens separately and one as `hello` with the harness tokenizer. An index-only heading can affect rank. Charge its tokens to indexing and charge the prompt only for displayed text. [RAG scorer](../benchmarks/rag.mjs) · [Tokenizer offsets](../benchmarks/encoder.mjs)

Project only visible portions of `sourceRanges` back onto the original and union them per document. Compute recall on the annotated portions of source tokens. A complete hit requires every evidence span in one gold alternative to be visible, including spans that cross chunk boundaries. Repeated text earns evidence credit once. For precision, count each delivered token at most once when it supplies previously unseen gold content, and divide by actual delivered tokens. Test reversed retrieval order, a repeated header, duplicate body text in different sections and clipping inside a multi-token Unicode character. Keep the old scores under their original metric version and rerun the controls with the revised scorer. [Token-level evaluation precedent](https://www.trychroma.com/research/evaluating-chunking)

### Datasets and release rule

Use CUAD contracts and full QASPER papers for long-document retrieval. Render QASPER’s real headings and record annotation offsets while rendering. Use HotpotQA’s distractor and pooled indexes to check multi-document evidence. Give all matched arms the same rendered input. Map the plain-text control’s whitespace normalization explicitly. Ambiguous annotation matches count as reported exclusions. Synthetic fixtures cover parser correctness and performance.

Use **FinQA first** for tables. Its released development JSON has 143 of 883 examples with both `table_…` and `text_…` keys in `qa.gold_inds`. Those identify the required rows and text passages. Render the source table and surrounding prose once, emitting an offset map keyed by those IDs. Keep answers, programs and pre-ranked retrieval fields out of index text. Measure row-plus-prose coverage and report it as row-level evidence. Group pages from the same report together. TAT-QA’s raw development questions contain source type and relevant paragraph IDs, but omit equivalent row IDs. Defer using it for row-level scores until a verified alignment exists. Both releases are available as JSON. [FinQA development data](https://github.com/czyssrs/FinQA/blob/0f16e2867befa6840783e58be38c9efb9229d742/dataset/dev.json) · [TAT-QA development data](https://github.com/NExTplusplus/TAT-QA/blob/ec12a30c26365ff05face6ffc431aaff9cb67c91/dataset_raw/tatqa_dataset_dev.json)

Keep ConditionalQA for a later rule-and-exception study under its research terms, Natural Questions for HTML conversion alignment and HybridQA for table/link multi-hop. Code fixtures check source fidelity. Retrieval claims about code require real questions with labeled code evidence. [ConditionalQA and use terms](https://github.com/haitian-sun/ConditionalQA) · [Natural Questions](https://github.com/google-research-datasets/natural-questions) · [HybridQA](https://github.com/wenhuchen/HybridQA)

Use dense complete-evidence retrieval at 512 delivered tokens as the primary score. Give CUAD, QASPER, FinQA and pooled HotpotQA equal weight and report them individually. HotpotQA’s shortlist uses the same questions and is diagnostic. Report paired wins/losses per 100 questions and a seeded paired 95% bootstrap interval over independent document or question groups. If the interval includes zero, favor the simpler release and report the uncertainty. A small clear gain must also justify its maintenance and measured embedding cost. [Qu et al.](https://aclanthology.org/2025.findings-naacl.114/)

Log each tested configuration, decision, raw JSON, retrieval scores at all budgets, chunk-size distribution, calls, embedded tokens, latency and peak memory. Time the large-document path separately with a deterministic batch callback on one long section and thousands of short sections, including unique bodies, repeated text, code and tables. This exposes per-section calls, repeated string copying and memory growth. Keep A–B–C look-ahead excluded because similar endpoints say nothing about B. Forced short merges previously lost held-out hits and increased embedding work. Defer Ward clustering, parent/child trees and global partitioning until an observed failure justifies changing the scheduler.
