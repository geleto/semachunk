# Delimited text and JSON records

Keep `blocks`, `pack` and `semantic`, with `auto` as the selector. The plan covers the `separator` option for plain text and the `json` input format. Line packing matched recursion on two 40-row fixtures and kept all 1,998 individually fitting rows in a 2,000-event log within 500 characters. [Line benchmarks](../benchmarks/LOG.md#2026-11-25--delimited-records-and-json-plan-review)

`maxChunkSize` is a soft target per chunk in UTF-16 code units. It defaults to 500 for text and HTML and 1,024 for Markdown and JSON. `maxChunkTokens` defaults to `Infinity`, so the tokenizer stays idle. A finite value must be a positive safe integer and requires the embedding model’s synchronous `countTokens(text)`. Set `maxChunkSize: Infinity` for token-only sizing. [Token sizing measurements](../benchmarks/LOG.md#2026-11-25--token-sizing-and-json-field-retrieval)

## When text exceeds the token limit

Apply a finite `maxChunkTokens` to the body and to the exact text with the caller’s prefix. Split an oversized unit at legal source boundaries. Try joining a stranded unit to an adjacent piece when their combined text fits. For example, `cl100k_base` counts a bare `😀` as two tokens and ` 😀` as one. Stop after these local checks even if a different partition could fit.

If a piece still exceeds the limit, return it intact in source order with `tokenLimitExceeded: true` and continue. Keep fitting pieces on either side. Group adjacent over-limit pieces within the same source unit so a prefix that leaves no room returns the unit once. Retry without optional generated or repeated context before marking a piece. Preserve the caller’s prefix, original source ranges and format metadata. [Fallback checks and package comparison](../benchmarks/LOG.md#2026-11-25--preserving-text-that-exceeds-a-token-limit)

The token limit is a hard ceiling for every string sent to the embedding callback. Treat marked pieces as boundaries for packing, overlap and semantic merging. Skip them in every embedding batch, including similarity scoring, prefetching and final vectors. A marked chunk has no `embedding`, even with `returnEmbedding: true`. Fitting chunks follow the ordinary batching rules. A caller-supplied tokenizer or provider that throws still reports its own error.

## Delimited text

- Accept a nonempty string `separator` only for explicit plain-text `blocks` or `pack`. Validate it before resolving `auto`, including for empty input. Treat `undefined` as omitted. Reject other nonstrings and `excludeNonLetterSentences: true` with a separator. Preserve plain-text locale validation. The locale does not affect literal matching. Keep the existing JavaScript behavior for unknown option names.
- Find literal, nonoverlapping matches in the original input. Count LF and CRLF as the same newline in both arguments. A lone CR matches only a lone CR. Match Unicode code points without splitting surrogate pairs. Escape regex metacharacters. Splitting `|||` on `||` leaves `|`.
- Trim record edges using JavaScript `trim()` whitespace and skip blank records. `blocks` emits each remaining record. `pack` appends consecutive records until the next join fails, preserving the exact slice with interior whitespace and separators. `|a||b|` gives `a` and `b` as blocks, or `a||b` together. Use `packedRanges` on inclusive record indexes and compare source offsets for the soft target before slicing. [Range packer](../src/packing.js)
- The default soft target is 500 UTF-16 units. A single record may exceed it. Zero disables joins and `Infinity` permits token-only sizing. Check each record against the token cap **before joining**, even when a larger slice would tokenize shorter. Split an over-cap record with whitespace-preserving `splitSpans` and flush on both sides. Packed overlap takes a suffix of whole records including interior gaps, measured in tokens with a finite cap and UTF-16 units otherwise. Each chunk takes fresh input. Split records are barriers. `blocks` rejects positive overlap. [Token splitter](../src/token-limit.js)
- A newline separator handles raw JSON Lines and single-line CSV rows. Later CSV chunks lose the header. When column names matter or fields contain line breaks, parse CSV upstream. Use row objects for unique headers or keep the header and positional values for duplicate names. For Markdown tables, escape literal pipes and encode line breaks within cells. The Markdown splitter repeats the header when it fits with the row.

## JSON records

The implemented single-child baseline keeps scalar values intact unless a hard token cap requires a split. For the next change, pack long strings at existing line and sentence boundaries and protect uninterrupted runs of non-space printable ASCII, including URLs with query strings. Use this rule for every structured candidate. [String policy comparison](../benchmarks/LOG.md#2026-11-25--json-string-boundaries-and-identifier-retrieval) · [Identifier audit](../benchmarks/LOG.md#2026-11-25--implementation-surface-audit-of-the-delimited-text-and-json-plan)

Lazy-load optional `jsonc-parser@^3.3.1` for JSON. Use the package with its license intact and write original chunking logic and tests. Only a missing parser gets the `npm install --include=optional` hint. [Parser and license](https://github.com/microsoft/node-jsonc-parser/tree/v3.3.1)

- Accept `blocks` and resolve JSON `auto` to `blocks` with either `combineChunks` value and with or without a callback. Reject other explicit strategies, positive overlap and sentence filtering. Parse one document after stripping at most one initial BOM. Set `disallowComments: true`, `allowTrailingComma: false` and `allowEmptyContent: true`. Reject the first diagnostic at its original UTF-16 offset before embedding. Only an absent root with no diagnostics returns no chunks. JSON whitespace is space, tab, CR or LF. Restore the BOM offset in all source ranges. [JSON grammar](https://www.rfc-editor.org/rfc/rfc8259)
- Walk the tree in source order with an explicit stack. In an object visit each property's **value**, using its decoded key for the path and its opening key quote as the member's start. Array items use their value span and current index. Wrap only stack exhaustion from `parseTree` in a JSON nesting error with its cause. The supported depth depends on the runtime. [Parser source](https://github.com/microsoft/node-jsonc-parser/blob/v3.3.1/src/impl/parser.ts)
- Each item of a nonempty root array is a record. Every other root, including `[]` and a keyed root object, is one record. Use a root array when entities must stay separate. `[1,2]` therefore starts at `/0` and `/1`, while a fitting `{"xs":[1,2]}` stays at the root. Default to 1,024 UTF-16 units of raw body including interior indentation, commas and escape spellings. On descent replace an oversized member or wrapper with its children. The baseline emits fitting spans intact and each detached child separately. Zero descends through every nonempty container and emits each scalar or empty container at its own pointer, with hard splits if needed. `Infinity` keeps records whole until the hard cap requires descent.
- A single sentence, another scalar or an empty container can exceed the soft target. Hard cuts preserve each raw code point, each JSON escape, and both halves of a decoded surrogate pair. Test the four ways to write such a pair using literal and `\uXXXX` halves. Preserve lone surrogates as written. When a cut falls inside a protected span, use its nearest legal edge. Search the sorted spans by position. A full rescan took 32,319 inspections for 1,024 escapes and 130,175 for 2,048 at a 96-unit cap. Keep Markdown’s existing rules for splittable spans. [Span splitter](../src/token-limit.js)
- Chunks are source excerpts and can contain a partial JSON value. A singleton or fragment keeps its value’s `jsonPointer`. A group of two or more siblings uses the parent’s pointer. The root is `""`. Encode `~` then `/` as `~0` and `~1`. RFC 6901 pointer evaluation fails when the referenced object member name occurs more than once. Identify those occurrences by source range. Ancestor keys and later fields may be absent from the text. [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901)

## Choosing a JSON layout

Compare single-child descent with greedy packing of adjacent siblings in the same parent and root record. A packed body spans the first member’s start through the last member’s end, including gaps and commas. Flush before and after a child that requires descent or soft string splitting, or exceeds the token cap on its own with the required caller prefix. Its fragments keep its pointer. Otherwise try appending it with the open group’s context. If the join fails, flush and size the child with the context for its new group. At size zero, emit leaves separately.

Compare both layouts with and without repeating preceding scalar fields. Only objects supply context. Immediately before the detached body’s first member, take the longest contiguous suffix of scalar members whose raw slice fits 128 UTF-16 units including gaps. Keep that range fixed while growing a group and across fragments of the same member. Descendants inherit it until a nearer qualifying object range replaces it. Clear it at each root record. Emit the context once, a newline, then the body, mapping both slices. Test later identifiers, an unrelated preceding scalar, a nested replacement and a long `{name,description}` record.

Only the raw body consumes the soft target. Repetition adds at most 129 UTF-16 units. Count the assembled text with and without the caller’s prefix. If a fresh nonempty container fits alone and optional context would cause a split, keep the container whole and omit the context. For a terminal, size the pieces with context first. If any piece still exceeds the cap, discard the tentative fragments and retry the original terminal without optional context. Apply the shared overflow rule to that result. Test a container costing nine tokens alone and thirteen with context, and a terminal where overflow occurs after several fitting fragments.

Test omitting a standalone field only when its sole range exactly matches a context range on every surviving piece of the detached body. Require at least one such piece and compare source offsets. Keep mixed ranges, partial repetitions and every leaf body at size zero. Omission can remove an addressable title chunk.

If omission is nominated, compare it with the same layout retaining the field. Apply the ordinary and attributable loss guards to the pair. For title-only lookup, use the first record in source order whose standalone title would actually be omitted in that rendering. Freeze this query for both variants, report the eligible-pool denominator and skip renderings with none. Packed title-first arrays have 1,758 eligible confirmation pools, but the first record qualifies in only 260. Require the correct record and full title in one hit, with a lower paired 95% limit of at least −1 point on the eligible pools. Report indexing costs. An inconclusive comparison leaves the simpler qualified layout in place.

### Scoring delivered evidence

Identify each supporting sentence by its record and original sentence index, excluding surrounding whitespace and JSON delimiters. Expose `deliver`’s already-clipped ranges with the ranked hit index, output offsets and source intervals. Use them directly for JSON scoring. A plain-text hit can intersect several records. Credit a decoded code point only when all its raw spelling is visible contiguously in one hit from its record. Adjacent source ranges can have a synthetic newline between them in the output. Check both coordinate systems before combining evidence. A split `\u00e9` or surrogate pair earns no character credit.

- **Ordinary completion** requires every distinct supporting fact. A fact can accumulate credited characters across hits from its record. Require all non-whitespace characters, including punctuation, and allow whitespace normalization at chunk joins. First measure unbudgeted source coverage from the uncut indexed ranges. Six necessary rows can cover every fact while five hits cannot deliver them. Report this indexing ceiling separately from ranked, clipped completion. Structured JSON must preserve complete spellings. For multi-range hits keep each clipped interval separately. Taking the minimum and maximum offsets can falsely credit omitted material. [Delivery and projections](../benchmarks/delivered-context.mjs)
- **Attributable completion** requires each supporting sentence and its full title together in one clipped hit from its record. Different facts can use different hits. Require the ordered, visible occurrence of each phrase. Match the full title including qualifiers in the decoded title or an original sentence from that record. Freeze case and word-boundary rules on development, including Unicode and titles ending in punctuation. Fixtures must reject a title supplied only by metadata, a title in another record, hits split across title and evidence, and unrelated output inserted inside either occurrence. Whitespace normalization at genuine joins is allowed.

### Long strings and identifier lookups

For a positive, finite `maxChunkSize`, measure the raw UTF-16 string value including its quotes. Validate the JSON locale once using the same function as text and Markdown, independent of field contents. Use decoded line breaks for an over-target value. In a line that alone exceeds the target, use the existing sentence splitter with the configured locale (default `en`). Reject a sentence edge between two non-space printable ASCII characters from U+0021 through U+007E. This keeps a URL or identifier in one piece even if the segmenter recognizes `?` or `!` inside it. Consecutive Chinese sentences can still split without spaces. Greedily pack the resulting units in source order. One unit may exceed the soft target. Use the same rule for root strings, array items and object string values. [Range packer](../src/packing.js) · [Sentence boundaries](../src/sentences.js)

Map chosen offsets in the decoded value to the original spelling. With no escapes the offset is the opening quote plus one plus the decoded offset. Otherwise scan the raw spelling in order, advancing six units for a Unicode escape, two for a short escape, and one per literal UTF-16 unit. Translate only the line and sentence edges needed for packing. Runs of CR, LF, U+2028 and U+2029 belong to the preceding text as in the benchmark. A decoded newline written as `\n` or `\u000a` is a boundary. A literal backslash followed by `n` is ordinary text. Attach the original key and colon to the first piece only. A long key alone cannot trigger a soft cut. Preserve each fragment’s pointer and half-open source range. Zero and `Infinity` skip soft string cuts. Size each piece with its caller prefix under the shared token-limit rule.

On development, freeze a single ordered sequence of nominees. Begin with single-child descent, then optionally qualify sibling packing, repetition **retaining** the standalone field, and finally omission. Test each addition against its immediate qualified parent with the same scalar and packing rules. Stop at the last qualified layout if an addition fails, including the direct full-frame and applicable subgroup loss guards against single-child descent for each possible winner. Freeze the better generic reference on ordinary completion across the two title-first views before confirmation. The benchmark owns the alternatives. Only the selected layout needs a public implementation.

Freeze the 4,084 title-disjoint hard training questions and the 151 with an oversized supporting record in either title-first view. ## Implementation and verification

Implement and verify the literal separator independently of the JSON layout comparison. Measure net runtime JavaScript separately from tests and benchmark code. Keep the strict JSON baseline available while comparing candidates.

Exercise the shared fallback through public text, HTML, Markdown and JSON calls. Use a mixed input, a prefix that makes every piece exceed the cap, and a tokenizer where joining the prefix to a body reduces the count. Assert which texts reach the provider during semantic scoring and final embedding with bounded and unbounded caches, including when final embeddings are disabled. Round-trip source ranges for visible and hidden prefixes. Compare text and overflow flags with and without a callback for the same `blocks` or `pack` layout.

1. **Delimited text (roughly 40–70 lines).** Add literal record spans to the existing packer and token splitter. Through `chunkText`, cover LF/CRLF equivalence, a lone CR beside CRLF, surrogate pairs and lone surrogates, metacharacters, numeric and blank records, zero and unlimited targets, hard caps, whole-record overlap and option errors. Compare layouts with the log and CSV fixtures.
2. **JSON records (baseline implemented).** Cover strict diagnostics, BOM, deeply nested inputs, empty containers, duplicate or escaped keys, huge numbers, root strings and string array items. Exercise zero and unlimited targets, prefixes, literal and escaped line breaks, Unicode sentence punctuation, and a long URL alone and within prose. For every surrogate spelling test a cap that fits and one that returns a marked, intact pair. Round-trip a key longer than the cap. Run packaged consumers with full dependencies, with optional dependencies omitted, with the JSON parser alone, and with the Markdown parsers alone. Check plain and delimited text, independent format loading, and each missing parser’s own diagnostic. Document the sizing cost of indentation and Unicode escapes.

Add `tokenLimitExceeded?: true` to the shared `Chunk` type. Both additions use half-open `sourceRanges` into the original input. `outputStart` indexes the displayed chunk. Slice a single body directly. If repetition ships, reuse the small Markdown parts renderer for multi-range results in a parser-independent module. Use the presence of ranges in the shared prefix and embedding step. A visible prefix shifts output offsets and a hidden one sets `embeddingText`. Identical texts at different positions keep separate results even when a provider batch shares a vector. Test exact indexing strings, range round-trips and zero provider calls for layouts alone. Document both features. Show how preserving paragraph breaks improves article retrieval and when an application needs a finite `maxChunkTokens` with its own tokenizer. Save the rerun command, input fingerprints, settings and paired per-question results with the benchmark report, and log the release decision.

Use `RangedChunk` for delimited text and declare `separator?: string | undefined`. For a legal plain-text call, a definite separator yields `RangedChunk`, an absent or explicitly undefined separator yields `Chunk`, and a possible separator yields their union. Keep definite and absent overloads ahead of the possibly present plain-text overload, then handle dynamic formats. Distribute the fallback over whole option alternatives so an inferred `JSON | delimited text` input retains that correlation. When only the vector type is explicit, TypeScript defaults subsequent type parameters. A mixed dynamic format may then return the conservative union. Cover each case, callback-free calls, Markdown and HTML with exact type equality. [Declarations](../src/index.d.ts) · [Type checks run by npm test](../tests/types/chunk-text.ts)

Keep recursion as a benchmark reference. Reconsider a public mode only if a title- or section-disjoint multiline retrieval comparison clears the existing one-point margin over the best single separator at comparable cost.
